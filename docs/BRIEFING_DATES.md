# 日付別ブリーフ

ホームと分野タブの「配信日」で日付を切り替えます。五つのタブ、検索、保存、詳細表示を維持し、選択日をタブ間で保持します。「最新へ」で最新号を再取得します。決算タブは従来の決算一覧、保存タブは個人の保存一覧であり日付絞り込みの対象外です。

## 編集データ

`config/editorial.json` は schema_version 1 を維持します。任意のトップレベル `briefings` を追加できます。

```json
{"briefings": {"2026-10-23": ["existing-article-id", "new-article-id"]}}
```

- マップがある日は指定IDだけをその日の詳報として選びます。記事自体の日時・内容・不変ハッシュは変更しません。
- マップのない日は記事の `published_at` を JST に変換した日付を使います。
- 最新表示では今日のマップがあれば使用し、従来どおり `published_at <= now < home_until` を必須にします。日付指定では期限切れ詳報も読めますが、未公開記事は表示しません。
- バリデータは実在するISO日付、未来でない日付、重複のない既存ID、記事のJST公開日以降の選定日を要求します。原稿を遡及公開したことにはしません。
- 日付別表示はその日の選定記事への参照です。原稿の改訂前スナップショットではなく、記事ごとの更新日時を表示します。

RSS見出しは従来の配信号スナップショットを利用し、直近14配信分の保存を変更しません。詳報のみ残る日は他の日のRSSを流用せず詳報だけ表示します。通信失敗・誤った日付のアーカイブは表示中の号を変更しません。遅い前回リクエストが新しい日付選択を上書きしないよう要求番号を照合します。

## 検証

- `python -m unittest discover -s tests -p 'test*.py'`
- `node tests/test_briefing_dates.js`
- `python tests/browser_editorial.py` は日付選択のChromium UI試験も実行します（外部通信を遮断したfetch/storage fixture）。実機Safari、ネイティブ保存、Service Workerキャッシュを検証したものではありません。

公開シェルのJS/CSSクエリ版を更新しています。Service Workerのnetwork-first動作とキャッシュ名前空間は変更しません。既に開いているタブへJSをホットロードする仕組みではなく、画面再読み込み後に新UIが適用されます。
